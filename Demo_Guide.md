## Likely viva questions

**Why did you change the application?** The original returned random trains and PNR data on
every render and its buttons did nothing. You cannot write an expected result for random output,
so we documented those defects first, then made the logic deterministic and testable.

**Difference between EP and BVA?** EP picks one value per class of equivalent inputs (e.g. any
age 1-120 is "valid"). BVA tests the edges of those classes (0, 1, 2, 119, 120, 121), where
off-by-one mistakes happen.

**When do you use a decision table?** When the result depends on a combination of conditions -
the concession depends on age band × gender × quota (8 rules); the refund on status × quota × hours.

**What is 0-switch coverage?** Every single valid transition of the state machine is tested
once. We also tested every invalid event (e.g. PROMOTE on a confirmed ticket) and longer paths.

**Why Vitest instead of JUnit?** The application is TypeScript; JUnit runs Java. Vitest has the
same structure (`describe/it/expect`, setup, assertions) and writes JUnit-format XML reports.

**Mutation testing - why, if coverage is 100%?** Stryker makes small changes to the code (e.g.
`>` → `>=`). If no test fails, the tests are too weak. At 100% line coverage, 87 mutants still
survived the first run; 30 targeted tests raised the score to 99.13%, and the 8 left are
equivalent mutants (they cannot change behaviour).

**What is the Page Object Model?** Each page is a class (`BookingPage`, `PaymentPage`…) that
hides the locators. When the UI was redesigned, only the page objects changed - not the tests.

**Which defect are you most proud of finding?** DEF-V2-02: the departure-time rule was
unit-tested and correct, but the results page never used it, so a train that left at 06:40 could
still be booked at 19:00. Only the system-level Selenium test caught it.

**A test that was wrong?** The first horizontal-overflow probe used `window.innerWidth`, which
includes the scrollbar, so it passed although a screenshot showed a scrollbar. Later,
`WebElement.clear()` silently failed on React inputs - we switched to user-like Ctrl+A / Delete.

**How do you know the "actual results" are real?** The execution log, metrics and Excel workbook
are generated by `tools/generate_reports.py` from the JUnit XML that the tools write.
